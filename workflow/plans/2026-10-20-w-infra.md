# W-INFRA Implementation Plan

> **For agents:** tick `- [ ]` -> `- [x]` as you finish each step, in this file, in the same commit as the work. Keep the branch state's Progress cell current (`AGENTS.md` § 2). Spec: [W-INFRA design](../specs/2026-10-20-w-infra-design.md).

## Scope
**Goal:** Stand up the mono-repo (`desktop/`, `backend/`, `frontend/`), local Postgres, CI for all three components and a hosted dev environment, so later workstreams add features only.
**In scope:** F1-F10, N1-N5 (spec Goals). T1-T8 are done on the `W-INFRA` branch; T9 is done by a human on `development` after the merge (SD10).
**Non-goals:** authentication and security filters (C70, C79; W-AUTH); domain model, services, JPA or ported JDBC (C74; W-DOMAIN); any AI code (C80); porting or deleting desktop features; production environment, domains, monitoring (W-DEPLOY); multi-instance deployment (C69, § Known Gaps); a frontend container. Never edit `PROJECT_STATE.md` or `docs/DeveloperGuide.md` on this branch.
**Risk tier:** Medium. Verification: every automated edge case has a named test; manual rows are recorded in the branch state; the N1 scan, N2 and N5 checks run in T8; CI is checked on a real run in T7.

**Commands** (Windows PowerShell; the CI equivalents run on Linux):
- Desktop: `cd desktop; .\gradlew test` and `.\gradlew build` (CI wraps in `xvfb-run -a`).
- Backend: `cd backend; .\gradlew test` and `.\gradlew build` (Docker must be running).
- Frontend: `cd frontend; npm test`, `npm run lint`, `npm run build`.

Test notes (intended shape, kept test-driven):
- `HealthEndpointTest` uses `java.net.http.HttpClient` against `localhost:{port}`. `upWhenDatabaseReachable` asserts status 200 and body exactly `{"status":"UP"}`. `otherActuatorPathsAre404` asserts 404 for `/actuator`, `/actuator/info`, `/actuator/env`, `/actuator/beans`. `queryParametersDoNotAddDetails` asserts the body is still exactly `{"status":"UP"}` with `?show-details=always`, `?details=true` and an `Authorization: Bearer x` header.
- `downThenUpWhenDatabaseLoginBlocked` (E7) avoids container pause, which hangs the health query. Open a separate admin JDBC connection first, then:
```java
admin.createStatement().execute("ALTER ROLE test NOLOGIN");
admin.createStatement().execute(
    "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname = current_database() AND pid <> pg_backend_pid()");
// poll /actuator/health every 500 ms up to 10 s (per-request timeout 8 s): expect 503 and body {"status":"DOWN"}
admin.createStatement().execute("ALTER ROLE test LOGIN");
// poll up to 10 s: expect 200 and {"status":"UP"}
```
(`test` is the Testcontainers default superuser.)
- `StartupFailureTest`: `assertTimeoutPreemptively(Duration.ofSeconds(20), ...)` around `new SpringApplicationBuilder(SnoozeShareApplication.class).profiles("dev").web(WebApplicationType.NONE).run("--spring.datasource.url=jdbc:postgresql://localhost:1/snoozeshare")` (a command-line argument: `properties(...)` is the lowest precedence and `application-dev.yml` would win, so the test would connect to a local Postgres); expect an exception, not a hang. Must not extend the Testcontainers base.
- `ProfileDefaultsTest`: load `application.yml` with `YamlPropertySourceLoader` and assert `spring.profiles.default` is `dev`. `ServerPortDefaultTest` and `ServerPortOverrideTest` are two top-level `@SpringBootTest(webEnvironment = NONE)` classes (the second with `properties = "PORT=18080"`) asserting `env.getProperty("server.port")` is `8080` and `18080`; both extend nothing and set `spring.autoconfigure.exclude` to `DataSourceAutoConfiguration`, `DataSourceTransactionManagerAutoConfiguration`, `JdbcTemplateAutoConfiguration`, `FlywayAutoConfiguration`, plus `management.health.db.enabled=false`.
- `ProdProfileTest.missingDatasourceVariable`: parameterized over `SPRING_DATASOURCE_URL`, `_USERNAME`, `_PASSWORD`; start a Testcontainers Postgres inside the test (no `@ServiceConnection` base) and pass its JDBC URL, user and password as the supplied variables, so the only possible startup failure is the omitted variable; run `.profiles("prod").web(NONE)` with the other variables plus `SNOOZESHARE_CORS_ALLOWED_ORIGIN=http://localhost:3000`; assert the exception's message chain contains the omitted variable name. Isolate from the machine with `Assumptions.assumeTrue(System.getenv(name) == null)` for the omitted variable.

// src/lib/env.ts (intended shape)
export function apiBaseUrl(): string {
  return process.env.NEXT_PUBLIC_API_BASE_URL ?? 'http://localhost:8080';
}
export function validateEnv(env: Record<string, string | undefined> = process.env): void {
  if (env.NODE_ENV !== 'production') return;
  const v = env.NEXT_PUBLIC_API_BASE_URL;
  if (!v) throw new Error('NEXT_PUBLIC_API_BASE_URL is required');
  if (!/^https?:\/\/[^/]+$/.test(v))
    throw new Error('NEXT_PUBLIC_API_BASE_URL must be an http(s) URL without a trailing slash');
}
