## 4. Architecture

**Persistence — Now:** W-DOMAIN's JPA model and repositories are merged; database-dependent service implementations and JDBC adapters use the shared `@ConditionalOnDatabase` condition, which matches unless datasource auto-configuration is excluded.

| Source | Standing choice |
|---|---|
| C129 | *(superseded by C132)* Persistence-backed services and adapters use the explicit property gate. |
| C132 | Database-dependent services and adapters use `@ConditionalOnDatabase`, matching the shared backend convention on `development`. |

**Host API — Now:** Protected Host controllers register only when `snoozeshare.security.enabled=true`, matching `HostIdentityResolver`; listing, calendar, booking decision, conversation, and wallet routes resolve host identity server-side and call services rather than repositories. The authenticated frontend adapter routes requests through `authenticatedFetch`; all Host listing, calendar, request, message, and wallet screens use API-backed state with fixture mode retained for presentation tests. Collection and history GETs return every matching owner-scoped row in deterministic order, with no page/size contract; the listings collection carries booking count and average review rating from two grouped queries filtered by the resolved Host ID. Listing cards preserve those metrics when their status response patches only the matching row. The calendar route loads listing detail independently from month data, retains the last successful month while the requested month loads in-grid, and starts its block range empty; calendar data remains month-bounded with at most 42 grid cells. Block-create conflicts return distinct 409 codes for booking overlap and prior host blocks, preferring the booking code if both sources overlap (C139). This accepts unbounded collection payloads and server/client memory use (C131). Wallet mutations retain the existing ledger transaction and wallet row lock, with events after commit; ambiguous failures refresh balance and statement without retrying.

| Source | Standing choice |
|---|---|
| C127 | Use stable ownership errors, bounded projections, and approved endpoint contracts. |
| C131 | Collection/history GETs return complete owner-scoped result lists; no pagination or collection-size cap. |

**Availability — Now:** Host month reads query only overlapping blocks and bookings; mutations use fresh PostgreSQL `SERIALIZABLE` transactions, audit in the transaction, retry SQLSTATE `40001` once, then publish the availability event after commit. API ranges are inclusive; persisted ranges remain half-open.

| Source | Standing choice |
|---|---|
| C127 | Calendar reads return a month projection; block writes/removals are atomic and auditable. |

## 5. Conventions

Host route content uses a full-width page frame; input value text is normal-weight, while field labels remain emphasized. Listings, requests, messages, and wallet keep the navbar fixed to the viewport and scroll long content internally; requests cap pending rows at four and let past rows use remaining height, while the wallet statement uses remaining height. Scrollable Host tables keep their header visible, including on horizontal overflow. Per C132, database-dependent service implementations and JDBC adapters use `@ConditionalOnDatabase`, matching the shared backend convention; datasource-free contexts must exclude datasource auto-configuration. The Host listing API controller is separately gated by `snoozeshare.security.enabled=true` so auth-disabled dev contexts do not register a route without its identity resolver.
