# Conventions

| Rule | Applies to | Source |
|---|---|---|
| Layout: `desktop/`, `backend/`, `frontend/`, root `config/checkstyle/`, `docs/`, `docker-compose.yml`, `.github/` | repo root | new in this spec (SD1-SD3) |
| Each Gradle project has its own wrapper, a copy of the version in `gradle/wrapper/gradle-wrapper.properties` before the move (Gradle 9.7.1) | `desktop/`, `backend/` | new in this spec (SD2) |
| Checkstyle: both builds use `toolVersion = '10.26.1'`, `configDirectory = file('../config/checkstyle')` and `configFile = file('../config/checkstyle/checkstyle.xml')`; suppressions load through `${config_loc}`, which Gradle sets from `configDirectory`. Backend violations are fixed in code, never suppressed | `desktop/`, `backend/` | SD3, N4 |
| Backend base package `com.snoozeshare`, deliberately the same as the desktop's so W-DOMAIN can move classes without renaming; the two components share no classpath, and a class is copied, never referenced, across them. Skeleton classes: `SnoozeShareApplication`, `config.CorsConfig`, `config.CorsProperties`; later packages follow Webapp design § 3.1 | `backend/` | Webapp design § 3.1 |
| Backend dependencies (exact versions come from the Spring Boot BOM except where noted): `spring-boot-starter-web`, `-actuator`, `-validation`, `-jdbc`, `org.postgresql:postgresql`, `flyway-core`, `flyway-database-postgresql`; test: `spring-boot-starter-test`, `spring-boot-testcontainers`, `org.testcontainers:postgresql`, `org.testcontainers:junit-jupiter`; no JPA, no Spring Security (SD7). Tests start Postgres through `@ServiceConnection` on one shared base class | `backend/` | SD5, SD7 |
| Versions: Spring Boot 3.5 line (latest 3.5.x GA at implementation, recorded in the branch state and README; T3 first confirms it supports a Java 25 toolchain); Java 25; Postgres 17; Node 22; Next.js 15; React as required by that Next.js; Tailwind CSS 4; Vitest with jsdom and Testing Library; ESLint with Next's default config; npm (not pnpm or yarn) | all | new in this spec (N2) |
| Settings: `snoozeshare.cors.allowed-origin` (env `SNOOZESHARE_CORS_ALLOWED_ORIGIN`); `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD`; `PORT`; `SPRING_PROFILES_ACTIVE` (`dev` or `prod`); the runtime keys listed in [api.md](api.md) | `backend/` | Webapp design § 6.2 |
| Local database: service `postgres`, image `postgres:17`, database `snoozeshare`, user `snoozeshare`, password `snoozeshare`, named volume `snoozeshare-pgdata`, host port `${POSTGRES_PORT:-5432}`, healthcheck `pg_isready`. Dev URL `jdbc:postgresql://localhost:${POSTGRES_PORT:5432}/snoozeshare` | `docker-compose.yml`, `application-dev.yml` | new in this spec |
| `application.yml` holds shared settings only; `application-dev.yml` non-secret local defaults (committed); `application-prod.yml` reads env vars with no defaults; `application-local.yml` is gitignored and imported with `optional:`. Neon URLs need `?sslmode=require`, stated in the runbook | `backend/` | SD8 |
| `.gitignore` adds `node_modules/`, `.next/`, `.env*.local`, `backend/build/`, `desktop/build/`, `application-local.yml`; T1 owns all of it | repo root | new in this spec |
| Frontend: `src/lib/env.ts` is the only reader of `NEXT_PUBLIC_API_BASE_URL`; `src/lib/api.ts` calls `apiBaseUrl()`; `.env.example` documents the variable; `.npmrc` sets `engine-strict=true` | `frontend/` | new in this spec |
| CI keeps its triggers: `checkstyle` on every push, `build` on pull requests and pushes to `development` and `main`; no path filters. Step names start with `desktop:`, `backend:` or `frontend:`; Node comes from `setup-node` with `node-version-file: frontend/.nvmrc`; the frontend build step sets `NEXT_PUBLIC_API_BASE_URL=http://localhost:8080`; failure artifacts upload from `desktop/build/reports`, `backend/build/reports` and are skipped for the frontend. Docker is preinstalled on `ubuntu-latest` | `.github/workflows/ci.yml` | C60, SD4 |
| The desktop move is one commit made of renames plus only these edits: the Checkstyle `configDirectory` and `configFile` paths in `desktop/build.gradle`, the `working-directory` and artifact paths in `ci.yml`, and `.gitignore`. No other content changes. The tree builds at that commit | git | AGENTS.md § 6 |
| Account-bound steps (Railway, Vercel, Neon sign-up, tokens, environment variables) are done by a human and recorded in `docs/runbooks/dev-environment.md` with the deployment order: Railway first, then Vercel with `NEXT_PUBLIC_API_BASE_URL` set to the Railway URL, then Railway's `SNOOZESHARE_CORS_ALLOWED_ORIGIN` set to Vercel's stable production domain and redeployed. The runbook states prominently that Vercel's Production Branch is `development` until W-DEPLOY. An agent never enters credentials | deployment | SD6, SD9 |
| Container: `backend/Dockerfile` is multi-stage (`gradle:9.7.1-jdk25` builds with `./gradlew bootJar`, `eclipse-temurin:25-jre` runs `java -jar app.jar`), build context `backend/`; `backend/railway.json` sets builder `DOCKERFILE` and `healthcheckPath` `/actuator/health`; the Railway service root directory is `backend` | `backend/` | Webapp design § 6 |
