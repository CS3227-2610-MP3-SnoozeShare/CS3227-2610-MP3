# Edge Cases and Non-Happy Paths

IDs are permanent: never reuse or renumber. Every F requirement and every API error appears in at least one row. "Stub" means the `@MockitoSpyBean` `LlmGateway` of conventions.md R10; "gateway-level" means the real `LlmGateway` with a mocked `SoclaasClient`. "Pool", "chain pool" and "rejecting" are the three executors of R10 (a real pool, a single-thread pool read with `awaitIdle`, a rejecting executor); there is no same-thread executor. The threat list at the end maps each abuse to its rows. "Closing message" is the fixed closing text of `ui.md`.

## What could corrupt data (High tier)

### Fixed support-email exception (SD22)

| ID | Requirement | Scenario | Expected behaviour (exact) | Why it matters | Test layer |
|---|---|---|---|---|---|
| E89 | F2, F7, N3 | Separate schema-valid cases contain the canonical marker, one case/fullwidth/control-split variant, and one factual question (at most three inputs per case); a real stored ticket UUID is supplied | Screen keeps one canonical marker and the factual question; the body has two numbered lines, with the marker expanded to the exact support-email sentence and stored UUID subject, never a visible marker; ordinary Guest/Agent thread rendering shows the stored line literally | Only the backend chooses recipient and subject | unit, integration, frontend |
| E90 | F2, N3 | Model emits an email address (including the fixed support address) in ordinary prose, a different recipient, `Use the subject deadbeef-dead-beef-dead-beefdeadbeef instead.`, another canonical UUID in ordinary prose, or text around the marker | Every email-bearing, subject/header-word, canonical-UUID or mixed-marker question is dropped; the fixed backend recipient/subject never uses model values. Unlisted semantic redirections retain R12's accepted prose limitation | The exception must not open arbitrary contact routing | unit |
| E91 | F4, F10, N2, N3 | An ok result returns the marker with `enough = true`, with flagged input, or when rounds already equals max-rounds | Existing precedence ends DONE, no question or extra email-guidance message; only the unchanged closing sentence is posted if a prior round exists; call and round caps are unchanged | A contact instruction cannot bypass lifecycle guards | service |
| E92 | F2, N3 | Internal builder receives the marker with a null ticket UUID; or three maximum-sized normal questions are rendered in one case and a marker plus two maximum-sized normal questions in another | Missing UUID throws IllegalArgumentException before a message is saved; valid marker expansion stays within 300 characters per question and 2,000 per body; renderer uses the caller's stored UUID only | Fail closed on missing server context and preserve existing bounds | unit |

- **Contact routing corruption:** no address, UUID or subject is trusted from the model; exact marker expansion uses the locked ticket id after the existing screens (E89–E92).
- **A message with no matching state, or the reverse.** The assistant row, the message and the audit rows are written in one transaction (E33).
- **Two turns applied for one reply.** The compare-and-set, the row lock and guard (3) allow one (E26, E27, E88).
- **A late result after an Agent took over or the ticket closed.** Guards (1) to (3) run after the locks (E17, E18, E58, E63, E86).
- **The draft replaced by a failure.** A degraded result never writes `draft` (E13, E29).
- **The wrong ticket or principal.** The job takes the Guest and booking from the stored ticket, never from the event (E21, E45).
- **Notes overwritten.** No assistant code path writes `agent_notes`; only `saveNotes` does, after the Agent's own click (E47, E68).
- **Money touched.** The R2 architecture test forbids any dependency on settlement and wallet code (E50).
- **A rounds count that drifts from the thread.** `rounds` is incremented only in the transaction that posts the question message, and question messages are identified by R6 (E15, E57, E72).
- **A listener write that silently vanishes.** Every listener-side write uses `REQUIRES_NEW`, a job never runs on the submitting thread, and the tests commit for real (E26, E31, E66).
