# Conventions

Existing § Conventions are cited, not restated: the role AI rules (call `LlmGateway.run` outside a transaction, principal from the stored data, ASSISTANT turns from stored history only, server-built trusted context, act on `flagged`, plain-text rendering), the `ai` package import rule, `@ConditionalOnDatabase`, one audit row per change through `AuditRecord.builder`, `RowLocks`, the `jsonPath` contract test, and "spy and mock beans live in the shared base class". The rules below are new or applied here.

| Rule | Applies to | Source |
|---|---|---|
| R1 Assistant code lives in `com.snoozeshare.service.assistant`; it imports only the public types of `com.snoozeshare.ai` (`LlmGateway`, `AiFeature`, `OutputSpec`, `LlmCall`, `LlmResult`, `Turn`, `TurnRole`, `AuditContext`, `ModelTier`, `LlmErrorCode`). The entity is `domain.model.TicketAssistant`, the repository `repository.TicketAssistantRepository`, the response `api.response.AssistantResponse`, its conversion in `api.mapper`. Every bean carries `@ConditionalOnDatabase`, and the listeners and executor also require `snoozeshare.assistant.enabled` | new classes | new in this spec; § Conventions (`ai` import rule, `@ConditionalOnDatabase`) |
| R2 An architecture test fails the build if anything in `service.assistant` depends on `TicketService`, `DisputeSettlementService`, `TransactionService`, `LedgerWriter`, `WalletService`, `BookingService`, `AccountGovernanceService` or any class in `domain.settlement` | `service.assistant` | new in this spec (the assistant can read and talk, never settle: C20, C22) |
| R3 Settings are one `@ConfigurationProperties("snoozeshare.assistant")` record, `AssistantProperties`, validated at startup; an out-of-range value fails startup with a message naming the key and the allowed range | configuration | new in this spec; mirrors the gateway's validation |
| R4 Question screen. For each model question in order: replace every run of whitespace (including line breaks) with one space and trim; drop it if blank; drop it if it equals an earlier kept question ignoring case; drop it if it matches any of these case-insensitive patterns: `\b(we\|i)\s+(will\|'ll\|shall\|can)\b`, `\byou\s+(will\|'ll\|are going to)\s+(be\s+)?(get\|receive\|refunded\|reimbursed\|compensated\|paid\|credited)\b`, `\bwill\s+be\s+(refunded\|reimbursed\|compensated\|credited\|approved)\b`, `\b(guarantee\|guaranteed\|promise\|promised\|assure\|assured)\b`, `\b(your\|the)\s+(claim\|request\|ticket)\s+(is\|has been\|will be)\s+(approved\|accepted\|rejected\|denied)\b`. (In this table each `\|` is the regex alternation bar `|`.) Keep at most the first 3 survivors. The screen can drop a harmless question that contains "promise"; that costs one question and is accepted over letting a promise reach a Guest | question text before it is posted | new in this spec (SD6) |
| R5 Draft template, exactly these lines in this order, each section's items as `- {item}` lines and `- none` when the list is empty: `AI-assisted draft. Everything below comes from the Guest's own statements and is unverified.`; if flagged: `WARNING: the Guest's text matched a prompt-injection pattern. Read it with care.`; if the gateway reported `truncated`: `Note: long Guest text was shortened before analysis.`; `Summary: {summary}`; `Timeline (as reported):`; `Guest claims:`; `Evidence mentioned:`; `Still unknown:`; `Points to raise with the Host:`. Newlines inside any model string are replaced by one space. If the result exceeds 4,000 characters it is cut at the last whole line that leaves room for three more characters and `...` is appended | `ticket_assistants.draft` | new in this spec (SD7) |
| R6 Message bodies are exactly the fixed strings of `ui.md` with the screened questions numbered from 1; the author is the SYSTEM user and the channel is GUEST; the `Automated assistant` label is added by the UI, not stored | `MessageService.postAssistant` | new in this spec |
| R7 `AuditAction` gains `ASSISTANT_STATE` and `ASSISTANT_MESSAGE` (appended after `AI_CALL_REJECTED`). The Agent audit screen lists actions from the enum; the plan verifies its labels and filters show the new constants without a blank or an error | `domain.enums.AuditAction`, Agent audit UI | § 4.8 (C28) applied |
| R8 Lock order in the applier: `RowLocks.timeout()`, then the ticket row, then the `ticket_assistants` row, matching the Agent mutations that take the ticket row first | applier | § 4.16 (Locking convention) |
| R9 All time comes from the injected `Clock`: `updated_at`, `draft_updated_at`, `created_at` and the `stale` calculation | assistant code | new in this spec |
| R10 Tests replace `assistantExecutor` with a same-thread executor so jobs run deterministically, control gateway results through a stubbed `LlmGateway` registered in the shared integration base class, and never contact SoCLaaS; the gateway's own mock mode is used only for the end-to-end check of the mock reply | backend tests | § Conventions (shared base class); new in this spec |
| R11 The frontend shows assistant and thread text only as text nodes; a test renders a draft containing `<img src=x onerror=alert(1)>` and `**bold**` and asserts both appear literally | frontend components | § Conventions (plain-text rendering) |
| R12 The branch state's § Known Gaps records the accepted limitations of this feature at fold time: a job in flight at a restart is lost and its row stays `PENDING` (shown as stale); the question screen can drop harmless questions; the assistant does not re-run after `UNAVAILABLE`; assistant output is bounded by the same weaknesses as the gateway's (steered prose that matches no pattern passes validation) | branch state | new in this spec |
