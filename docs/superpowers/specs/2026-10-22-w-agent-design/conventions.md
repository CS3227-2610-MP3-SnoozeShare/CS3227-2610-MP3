# Conventions

Existing rules are cited by name; the table lists only rules new or applied here. These become the web layering rules W-GUEST and W-HOST follow (SD12).

| Rule | Applies to | Source |
|---|---|---|
| Controllers live in `com.snoozeshare.api.controller.<role>`; request and response records stay in `api.request` and `api.response`, conversions in `api.mapper` (C73) | backend | C73; new in this spec |
| ArchUnit (`com.tngtech.archunit:archunit-junit5`, test scope, added to `backend/build.gradle`) enforces in `ApiLayerTest`: no class in `api.controller..` declares a field, parameter or return type, or depends on a class, from `repository..`, `domain.model..` or `jakarta.persistence..`; none depends on `LedgerWriter`, `WalletService` or `AuditService`; every `UUID` parameter of a controller method is annotated `@PathVariable` or `@CurrentUserId`. Each rule uses `allowEmptyShould(true)` (wave 1 has no controller yet) and is proved by a fixture class in the test sources that breaks it. Audit reads go through `AuditQueryService`, never `AuditService` | backend tests | new in this spec (N2, N3, N6) |
| The acting user id comes only from `@CurrentUserId` (`com.snoozeshare.api.CurrentUserId`, resolved by `CurrentUserIdResolver`, registered by an `ApiWebConfig` that is conditional on `snoozeshare.security.enabled=true`; the request attribute key is `CurrentUserIdResolver.ATTRIBUTE`) | backend | C92; new in this spec |
| Request records use `@JsonIgnoreProperties(ignoreUnknown = false)` and bean validation; string fields carry `@Size` limits from api.md. Unknown-property rejection relies on `fail-on-unknown-properties: true` in `application.yml`, pinned by a test | `api.request` | existing records; new limits |
| Domain failures stay `IllegalArgumentException` (invalid input, 400) and `IllegalStateException` (state conflict, 409); a missing ticket, user, category or message thread throws `NotFoundException extends IllegalArgumentException` (404) | services | SD7 |
| Service exception messages are end-user text with no ids, names, SQL or class names | services | new in this spec (E40) |
| One mutating service call per endpoint; a follow-up read through `DisputeQueryService` is allowed; no controller opens a transaction, writes an audit row or calls a repository (N3) | controllers | existing service transaction rule |
| A service that mutates a ticket or suspends or reactivates a user loads that row with `findByIdForUpdate` (`@Lock(PESSIMISTIC_WRITE)` with an explicit `@Query`, and `RowLocks.timeout()` first, which runs `SET LOCAL lock_timeout = '5000ms'` because the PostgreSQL dialect ignores the JPA lock-timeout hint) as its first read of that row, before any other read of it or of rows derived from it, because Hibernate does not refresh an entity that is already loaded in the transaction (SD10, SD19) | services | new in this spec |
| Only exceptions thrown from `com.snoozeshare.service` or `com.snoozeshare.domain` have their message sent to the client; all others get a fixed message | `ApiExceptionHandler` | new in this spec (SD21) |
| Errors are `{code, message, requestId}`; the request id is generated per error and logged with status, code, path and agent id; reasons, notes, message bodies and exception messages are never logged (N4) | backend | C96; new in this spec |
| Money in JSON is a number with at most 2 decimals; the frontend never adds, subtracts or compares money (it checks only the decimal format) and takes preset amounts from the server (`escrowAmount`); display is `SGD` plus two decimals | both | N2; new in this spec |
| The frontend calls the backend only through `authenticatedFetch` and the typed helpers in `src/lib/agent-api/<area>.ts`; the JSON helper in `src/lib/api.ts` returns `undefined` for a 204 and never calls `.json()` on it; `src/lib/env.ts` stays the only reader of `NEXT_PUBLIC_API_BASE_URL` | frontend | existing convention |
| Agent components live in `src/components/agent/`; pages stay thin and under `src/app/agent/`; no agent code imports from `components/host/` | frontend | new in this spec |
| Polling hooks fetch only while `document.visibilityState === 'visible'`, clear their timers on unmount and ignore a response that arrives after a newer request started | frontend | C78; new in this spec |
| Tests: backend controller tests extend `PostgresIntegrationTest` with security enabled and the Firebase token verifier test double the auth tests use; `@MockitoSpyBean` on real services and `LedgerWriter` is allowed to assert calls and inject faults; log assertions use a Logback `ListAppender`; concurrency tests use two threads, a `CountDownLatch` and committed transactions; frontend tests use Vitest with a mocked `authenticatedFetch`; no test hard-codes a future date; each E-row names its layer | both | existing test conventions |
| Contract: backend controller tests assert response field names with `jsonPath`; frontend tests build their fixtures with the same names | both | new in this spec |
| Commits: one logical change each, green build, the branch state updated in the same commit or the next (`AGENTS.md` § 6) | repo | AGENTS.md § 6 |
