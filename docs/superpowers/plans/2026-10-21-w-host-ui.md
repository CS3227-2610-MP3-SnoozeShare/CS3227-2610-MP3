# W-HOST Fall Light UI Implementation Plan

> **For agents:** tick `- [ ]` -> `- [x]` as each step is completed, in this file, in the same commit as the work. Keep the branch state's Progress cell current. Spec: [W-HOST Fall Light UI design](../specs/2026-10-21-w-host-ui-design.md).

## Scope

**Goal:** Build the Host frontend screens to match the supplied Claude artifact's Fall Light styling and layout, using synthetic fixtures until W-DOMAIN provides authenticated domain APIs.

**In scope:** F1–F10, N1–N5; Host shell and routes, shared Fall Light primitives, fixture provider, listings, listing detail/form, calendar, requests, messages, wallet, local-only presentation interactions, accessibility and visual verification.

**Non-goals:** Backend Host controllers/services/repositories/migrations/API DTOs; real domain mutations; Firebase/auth changes; Guest/Agent page redesign; payment, polling, AI, or image-hosting work. Do not implement the accepted frontend-guard limitation as backend authorization; do not change W-DOMAIN-owned persistence or wallet operations.

**Risk tier:** Medium — role-gated screens present synthetic booking and wallet information, but this slice adds no API, persistence, or domain mutation.
