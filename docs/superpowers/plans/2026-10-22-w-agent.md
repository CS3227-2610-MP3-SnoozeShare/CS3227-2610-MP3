## Scope
**Goal:** A signed-in Support Agent can work disputes, accounts, the audit log and ticket categories on the web through `/api/agent/**` and the Next.js pages under `/agent`, with the shared REST foundation Guest and Host will reuse.
**In scope:** F1-F16 and N1-N8 of the spec; the existing-code changes listed in the spec's `api.md` § Existing files touched (ticket and user row locks, `unassignedCount`, `listGovernableAccounts`, `AuditQueryService`, audit zone, not-found exception, request constraints, `agentNotes` move).
**Non-goals:** force complete or cancel (C22); agent AI (W-AI-AGENT); Guest and Host endpoints and pages; unassign in the UI; agent unread counts; Firebase changes on suspension; queue and accounts pagination; seed data; WebSocket; per-agent rate limits. No Known Gap is implemented or reversed.
**Risk tier:** High. Every backend task is test-first, the two lock tasks (T2, T4) need real two-thread tests, and T12 re-runs both component builds in full and walks each flow in a browser.

**Commands used below.** Backend (needs Docker; Windows traps in `PROJECT_STATE.md` § Conventions: keep the Gradle daemon warm, run Checkstyle and tests in separate invocations): `cd backend; .\gradlew checkstyleMain checkstyleTest`, then `cd backend; .\gradlew test --tests <class>` for one class or `.\gradlew test` for all. Frontend (Node 22): `cd frontend; npm test -- <path>`, `npm run lint`, `npm run build` with `NEXT_PUBLIC_API_BASE_URL` and the six `NEXT_PUBLIC_FIREBASE_*` variables set to the CI placeholder values in `.github/workflows/ci.yml` (the build fails without them). **BUILD** means: backend Checkstyle, backend tests, frontend `npm test`, `npm run lint`, `npm run build`, in that order.
