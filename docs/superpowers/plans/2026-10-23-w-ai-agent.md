## Scope

**Goal:** Gather missing facts from Guest tickets through bounded automated questions and keep an Agent-only draft for manual insertion into notes.
**In scope:** SD22 fixed backend support-email expansion; F1–F11 and N1–N6: persistence, SYSTEM posting, feature registration and screens, asynchronous orchestration, triggers, Agent read contract and panel, Guest labels, configuration, operations and verification.
**Non-goals:** Host-facing automation, new roles, settlement or wallet writes, automatic notes writes, rerun/stop controls, Agent text in prompts, gateway changes, retention, pagination, recovery sweeps or distributed deployment. Preserve C20/C22, C69, C80, C101 and the gateway Known Gaps. No Developer Guide edits on this feature branch.
**Risk tier:** High, inherited from the approved spec and C67. Verify real PostgreSQL commits, lock ordering, late-result guards, private-data boundaries, output screens and audit atomicity. Reuse the gateway; do not redesign its accepted limitations.

## Verified integration details

- V001–V005 exist. V003's inline message CHECK is `messages_author_role_check`; V004's SYSTEM id matches `AuditService.SYSTEM_ACTOR_ID`. TicketAssistant deliberately keys on `ticket_id`, an explicit exception to the ordinary entity `id` column convention required by the approved schema.
- `MessageServiceImpl.post` publishes through its own after-commit synchronization; `TicketServiceImpl.fileTicket` publishes inside its transaction. Use different listener annotations accordingly. Neither publisher needs modification.
- `MessageRepository.findThread` orders descending by timestamp then UUID. Reverse that database order; do not compare Java UUIDs using signed `UUID.compareTo` for the equal-timestamp PostgreSQL ordering. Query newer messages using PostgreSQL ordering or compare canonical UUID text consistently.
- Agent `Role` already includes SYSTEM. Guest `MessageResponse.authorRole` is currently `string`; T8 introduces a shared message-role union and label helper without widening authentication roles. `ConversationList` currently displays only counterpart names; T8 adds the specified stored last-body preview for ticket conversations.
- `DisputeDetailResponse.from` exists; `DisputeMapper` does not. Create `AssistantMapper` in `api.mapper` and call it from the response conversion. `DisputeQueryServiceImpl.detail` currently lacks `@Transactional`; T6 must add the read-only boundary specified by the spec.
- Assistant drafts may be 6,000 characters, while `SaveNotesRequest.notes` and the textarea currently cap notes at 4,000. Preserve full insertion and the existing save contract: no silent truncation, no automatic save, no enlarged limit. The Agent must edit an oversized combined value before saving; record this inherited UX limitation in branch Deviations/Handover and verify the existing safe validation error. This is not permission to change notes scope.
- Feature runtime beans are conditional on database presence and `snoozeshare.assistant.enabled=true` (default enabled). Read-side code must start when runtime beans are absent: read persistent rows independently and obtain configured/default max-rounds and stale threshold without requiring a gated runner, job or feature bean. Keep configuration binding usable for read projection; test disabled and datasource-free contexts.

Intended SQL (one Flyway PostgreSQL transaction; no seed regeneration):
```sql
CREATE TABLE ticket_assistants (
    ticket_id UUID PRIMARY KEY REFERENCES tickets(id),
    state VARCHAR(16) NOT NULL CHECK (state IN
        ('PENDING', 'WAITING_GUEST', 'DONE', 'STOPPED', 'UNAVAILABLE')),
    rounds SMALLINT NOT NULL DEFAULT 0 CHECK (rounds BETWEEN 0 AND 5),
    flagged BOOLEAN NOT NULL DEFAULT FALSE,
    draft TEXT CHECK (char_length(draft) <= 6000),
    draft_updated_at TIMESTAMPTZ,
    last_message_id UUID REFERENCES messages(id),
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL
);
-- V003's inline CHECK is named by PostgreSQL; migration test pins its name.
ALTER TABLE messages DROP CONSTRAINT IF EXISTS messages_author_role_check;
ALTER TABLE messages ADD CONSTRAINT messages_author_role_check
    CHECK (author_role IN ('GUEST', 'HOST', 'AGENT', 'SYSTEM'));
```

Native updates clear/flush stale persistence state. All writes require caller transactions; repository never submits jobs.
